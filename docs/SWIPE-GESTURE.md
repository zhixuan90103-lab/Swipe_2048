# 同手势族调研 — 四向一步滑

配套：[AGENTS.md](../AGENTS.md) · [ENGINEERING.md](./ENGINEERING.md) · [HAPTICS.md](./HAPTICS.md) · [SWIPE-SOURCES.md](./SWIPE-SOURCES.md)（有效来源与证据等级）

> 筛选器是 **操作合同**，不是「像 2048」。规则（合并 / 涂色 / 杀人 / RPG）另列。  
> 三轮检索（2026-08）：2048-like → 直进标签补漏 → 种子再跳。AMAZE 第一轮漏检，因误用内容品类当筛子。

## 0. 手势合同（唯一入选条件）

全部满足才算同操作：

1. 一次手势只表达 **一个方向**（上 / 下 / 左 / 右）。
2. 过阈值 **提交一手**；划多长、划多快 **不改变这一步的结果**。
3. 走多远由 **规则/几何** 算（撞墙、走一格、全体滑到头），不由手指行程算。
4. 结算未结束 **不接下一次**（或最多 queue 1 步）。
5. 该方向无任何合法变化 → **无效手势**（盘面不变，通常 nudges）。

**不当筛子：** 是否数字、是否合并、全体还是单体、有无关卡表、商店品类。

**默认排除：** 连线/画路径、点选落下、瞄准（力度/角度随手势变）、划多远走越远、跑酷变道+跳、拖单个块任意位移、十字路口可不撞墙转向（吃豆人）。

**灰区（先搜再验）：** 实时冲刺可排队转向；六向棋盘；冰格只是关卡机制的一部分（如 Chip's Challenge）。

日站更贴合同的标签：**壁にぶつかるまで移動する直進パズル**（不要只用 `games like 2048`）。

## 4. 只从操作上值得学的细节

不谈合并表、关卡、商业化。只谈手指 → 提交 → 锁 → 句号。

### 4.1 识别

- 主轴四向：`abs(dx)` vs `abs(dy)`，丢掉斜向。
- 阈值用 **设计像素**（390×844），建议格宽 ~20% 或 24–40 设计 px。
- 按下前 8–12px 死区；出死区后这根手指绑死棋盘直到松开。
- **按下点定归属：** 棋盘起划则整段是棋盘；按钮起划不启动滑。
- 只认第一指。
- 长度 / 速度 **不改变停点**（速度最多略缩动画，不算规则）。

### 4.2 提交（三选一，写死不混）

| 模型 | 代表 | 学什么 |
|------|------|--------|
| 过阈值立刻提交 | AMAZE、TotM | 脆、快 |
| 松手提交 | 偏策略盘 | 可改主意 |
| 按住预览 + 松手/过阈值提交 | Threes、Slayaway | 最值钱：结果先可读再落地；划回可取消 |

不要做成按住连续改向再发射（那是瞄准）。

### 4.3 锁

- 锁的是结算，不是手指离开。
- **锁到最长那段位移结束**（滑到头时近块先停仍不能再滑）。
- 走一格可锁更短。
- Animating：丢事件或 **queue 最多 1**。默认不要学 TotM「滚途中改向」。
- 无效 nudges 也占 120–180ms，防连打。

### 4.4 无效与句号

- 无效：整盘/单位弹 2–4px；更轻震动；**无刷新、无扣步**。无反应会狂滑。
- 有效结束在 **停住**：撞墙顿 + 震（AMAZE）；停点要可读（Slayaway 停人身旁不是重叠格）。
- 反馈锚在 **提交点** 和 **停点**，不要锚在松手（立刻提交模型里松手已晚）。

### 4.5 各作只偷操作

| 来源 | 偷 |
|------|----|
| Threes | 预览、划回取消、松手提交 |
| 2048 | 无效不结算、最长锁、滑距≠步数 |
| AMAZE | 立刻提交、撞墙句号、贴墙 nudges |
| TotM | 滚途中不转向；看完再滑 |
| Slayaway | 短划预演落点 |
| Slider Scouts | 同一识别可打很快（锁短、反馈脆） |

桌面方向键 = 同一 Resolve；**不要按住连发**（原作 2048 连走是坑）。

### 4.6 实现检查表

- [ ] 斜划只出四向之一
- [ ] 阈值在设计坐标（`clientToDesign`）
- [ ] letterbox 外忽略
- [ ] 长度/速度不改停点
- [ ] 棋盘 vs HUD 归属
- [ ] 提交模型唯一
- [ ] Animating 丢或 queue 1
- [ ] 锁到最远位移结束
- [ ] 无效 nudges、无副作用
- [ ] 停点有句号（震/顿）
- [ ] 键与滑同一套 Resolve

状态机建议：`Idle → SwipeRecognized → Resolving → Animating → Idle`。

## 5. 检索计划（修订后，防再漏 AMAZE）

1. 合同是唯一筛子；**禁止**只用 `games like 2048`。
2. 主检索式：`壁にぶつかるまで` OR `slide until (wall\|obstacle\|hit)` OR `ricochet robots` OR `一滑到底`。
3. 种子轮换：2048/Threes → AMAZE/Longcat/House Paint → Slayaway/Slider Scouts/割草。
4. 必点 APPLION「直进パズル」类似 10 选。
5. 每条验收三问：是否只选一个方向一整步？划的长度改不改结果？是方向还是画线/瞄准/拖单个？
6. 记录模板：`名称 | 桶 | 谁在动 | 停在哪 | 规则一句话 | 实时/回合 | iOS US App ID | 合同是否通过`

## 6. 对本项目的含义

- 输入层可 **共用一套**（识别 + 提交 + 锁 + 无效）。换玩法只换 **停点函数** 和 **提交模型**。
- 第一版玩法若做 2048：立刻提交 + 滑到头 + 无效 nudges + 最长锁；预览/Undo 后加。
- 触控走 `clientToDesign`；UI 只挂 `#ui-root`；震动见 [HAPTICS.md](./HAPTICS.md)；音效勿热路径 `new Audio()`（[AUDIO.md](./AUDIO.md)）。
- 未实现玩法前，本文只作调研，不改 `src/main.ts` 合同外的底座。
